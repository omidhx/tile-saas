**نیست (عمداً — قابلِ بازتولید):** `node_modules/` (~۶۵۳MB)، `.next/` (~۳۱۲MB)،
`test-results/`، `tsconfig.tsbuildinfo`. بعد از هر بازگردانی با `npm install` ساخته می‌شوند.

## گرفتنِ بکاپِ تازه

```powershell
$stamp = Get-Date -Format 'yyyy-MM-dd_HHmm'
$dest  = "W:\Claude Site\tile-saas\_backups\tile-saas_$stamp"
robocopy 'W:\Claude Site\tile-saas' $dest /MIR `
  /XD node_modules .next test-results _backups playwright-report blob-report `
  /XF tsconfig.tsbuildinfo /NFL /NDL /NP /R:1 /W:1
```
> `robocopy` با کدِ خروجیِ `0` یا `1` **موفق** است (۱ یعنی «فایل کپی شد»)؛ `≥8` یعنی خطا.

## بازگرداندن

بکاپ را **کنارِ** پروژه باز کن، نه رویش — تا قبل از جایگزینی بتوانی مقایسه کنی:

```powershell
robocopy 'W:\Claude Site\tile-saas\_backups\tile-saas_2026-08-13_2249' `
         'W:\Claude Site\tile-saas-restored' /MIR /NFL /NDL /NP
cd 'W:\Claude Site\tile-saas-restored\web'; npm install
```

اگر فقط چند فایل خراب شده، کلِ پروژه را برنگردان — همان فایل‌ها را از پوشه‌ی بکاپ کپی کن.

> **هشدار:** بازگرداندنِ کلِ پوشه، `.git` را هم برمی‌گرداند؛ یعنی هر کامیتی که **بعد از**
> تاریخِ بکاپ زده شده از بین می‌رود. اگر کامیتِ باارزشی بعد از آن داری، اول از آن branch/patch بگیر.

## نکته‌ی مهم

`_backups/` در `.gitignore` ریشه است و نباید کامیت شود: حجیم است، `.git` را تودرتو
تکرار می‌کند، و `web/.env` رازدار داخلش است. این بکاپ **روی همان درایو W:** است —
یعنی در برابر اشتباهِ ویرایش محافظت می‌کند، نه در برابرِ خرابیِ دیسک. برای آن، یک کپی
روی مقصدِ دیگر لازم است (همان توصیه‌ی `CLAUDE.md` درباره‌ی بک‌آپِ خارج از سرور).
